# C09 检索增强生成的幻觉检测与量化评估：项目实施指导

## 1. 文档定位

本项目面向三名具备深度学习基础的成员，目标是在单张显存不超过 12 GB 的消费级 GPU 上，完成一套可离线复现的 RAG 幻觉检测实验。项目优先保证任务闭环、实验可信、结果可复现和答辩逻辑清晰，在此基础上实现一个范围较小但可以被实验验证的方法改进。

本项目研究的重点是**检测和量化 RAG 回答中的幻觉**，不是训练一个更大的生成模型，也不把构建复杂应用界面作为主要工作。

核心问题可以表述为：

> 给定问题、检索证据和生成答案，能否比生成模型自评置信度更准确地判断回答是否出现幻觉，并进一步区分幻觉来自检索失败、证据冲突还是答案过时？

## 2. 必须达到的项目要求

### 2.1 核心研究目标

1. 搭建可离线复现的开放域问答 RAG 管道。
2. 基于 SQuAD 和 HotpotQA 构造不少于 300 条挑战样本。
3. 覆盖检索失败、证据冲突、答案过时三类场景。
4. 实现生成模型自评置信度基线。
5. 复现至少一个有论文、代码和公开权重的方法，选用 MiniCheck-Flan-T5-Large。
6. 提出并实现一个面向三类失败的轻量幻觉检测方法。
7. 以 ROC-AUC 为主指标，争取相对生成模型自评置信度取得至少 0.10 的绝对提升。
8. 使用不少于三个随机种子，报告均值和标准差。
9. 完成不少于三组消融实验、一次统计显著性检验和一组失败分析。
10. 人工抽检不少于 100 条样本。

### 2.2 “AUC 提升 0.10”的计算

生成模型自评置信度是一种基线评分方法，ROC-AUC 是评价该方法的指标。

如果模型输出“回答受到证据支持的置信度”为 \(c\)，则定义：

\[
r_{self}=1-c
\]

其中 \(r_{self}\) 是幻觉风险。对全部测试样本的风险分数和真实标签计算 ROC-AUC。

目标按绝对提升理解：

\[
\Delta AUC=AUC_{ours}-AUC_{self}\geq 0.10
\]

例如，自评基线 AUC 为 0.64，本方法 AUC 为 0.76，则绝对提升为 0.12，达到目标。

该数值是研究目标，不是允许伪造结果的硬性条件。未达到时必须如实报告并分析原因。

## 5. 固定技术栈

为控制实现复杂度，第一版统一采用以下组件：

| 模块 | 推荐方案 | 选择理由 |
|---|---|---|
| 开发语言 | Python 3.11 | 生态成熟，便于复现 |
| 深度学习 | PyTorch + Transformers | 支持本地开源模型 |
| 数据读取 | Hugging Face Datasets | 可直接获取公开数据 |
| 基础检索 | BM25（rank-bm25 或 Pyserini） | 简单、稳定、便于分析检索失败 |
| 语义向量 | all-MiniLM-L6-v2 | 轻量，用于证据匹配 |
| 生成模型 | Qwen2.5-3B-Instruct，4-bit 推理 | 12 GB 显存内可运行 |
| 证据关系 | DeBERTa-v3-base MNLI 类模型 | 输出蕴含、中立、矛盾概率 |
| 公开强基线 | MiniCheck-Flan-T5-Large（770M） | 有论文、代码、权重和公开评测 |
| 主判别器 | 逻辑回归或两层 MLP | 轻量、可解释、容易消融 |
| 实验管理 | YAML 配置 + CSV/JSONL 结果 | 不引入重型平台 |
| 可视化 | Matplotlib + Seaborn | 满足自绘图表要求 |

如果 Qwen2.5-3B-Instruct 在实际设备上运行困难，可降为同系列 1.5B 模型。整个项目只固定一个生成模型，避免把时间消耗在模型横向比较上。

## 6. 数据方案

### 6.1 核心公开数据

| 数据集 | 用途 | 获取方式 | 许可证 |
|---|---|---|---|
| SQuAD 1.1 | 单跳事实问答和可控证据修改 | `load_dataset("rajpurkar/squad")` | CC BY-SA 4.0 |
| SQuAD 2.0 | 无答案和拒答辅助验证 | `load_dataset("rajpurkar/squad_v2")` | CC BY-SA 4.0 |
| HotpotQA distractor | 多跳问答、干扰证据和检索失败 | `load_dataset("hotpotqa/hotpot_qa", "distractor")` | CC BY-SA 4.0 |

原始数据不提交到 GitHub。仓库只保存下载脚本、版本信息、校验信息和构造后的必要索引。

### 6.2 外部辅助数据

- RAGTruth：可用于检查检测器在自然生成幻觉上的泛化，但不作为核心训练集。
- RGB：可选取反事实和噪声子集作为补充测试。
- RAGBench：仅在资源允许时选取小规模子集，不运行完整 9 万余条数据。

MiniCheck 和 LettuceDetect 等模型可能使用过部分公开幻觉数据，外部测试必须注明可能存在的训练数据重叠。项目的主要结论以自行构造且按来源隔离的测试集为准。

### 6.3 计划数据规模

建议选取 450 个基础问题，形成一一对应的正常条件和挑战条件：

| 条件 | 基础问题数 | 说明 |
|---|---:|---|
| 正常证据 | 450 | 正确证据可检索且无冲突 |
| 检索失败 | 150 | 正确证据缺失或未进入 Top-K |
| 证据冲突 | 150 | 正确证据与可控矛盾证据共存 |
| 答案过时 | 150 | 旧版本与新版本事实共存 |

最终约得到 900 次问答记录，其中挑战条件 450 条，超过“挑战集不少于 300 例”的要求。

挑战条件不等于必然产生幻觉。模型可能正确拒答或抵抗错误证据，这些样本必须保留，不能为了平衡标签而删除成功案例。

### 6.4 数据划分

按照原始问题 ID 或来源文档进行分组划分：

- 训练集：60%；
- 验证集：20%；
- 测试集：20%。

同一个原始问题产生的正常版本和所有扰动版本必须进入同一集合。不得随机拆分生成后的记录，否则会发生数据泄漏。

为检查构造模板泄漏，至少保留一部分实体替换方式、冲突模板和时间表达模板，只在测试集中出现。

## 7. 挑战数据构造

### 7.1 检索失败

从包含标准答案的样本出发，采用以下一种或多种操作：

1. 从候选语料中移除正确段落；
2. 将正确段落排到 Top-K 之外；
3. 加入与问题词汇高度相似但不包含答案的干扰段落；
4. 保留部分多跳证据，删除完成推理所需的另一部分证据。

每条样本记录：

- 正确证据是否进入 Top-K；
- 正确证据最高排名；
- Top-1 与 Top-K 检索分数；
- 正确证据覆盖率；
- 所使用的扰动操作和随机种子。

### 7.2 证据冲突

在原始正确证据的关键事实上进行最小修改：

- 替换人物或组织；
- 替换地点；
- 替换数字；
- 替换日期；
- 反转明确关系。

同时保留正确证据和修改后的冲突证据，并改变两者的排序和数量比例。修改后的文本必须保存原始值、替换值和修改位置，标签由构造记录确定，不能再使用待评估的 NLI 模型生成真值。

### 7.3 答案过时

由于 SQuAD 和 HotpotQA 缺少统一的事实版本历史，采用可自动验证的受控版本化构造：

1. 从包含实体、年份、数字或职位关系的事实中抽取值 \(v_0\)；
2. 构造旧版本：在时间 \(t_0\) 时事实值为 \(v_0\)；
3. 构造更新版本：在时间 \(t_1\) 时事实值变为 \(v_1\)，且 \(t_1>t_0\)；
4. 将问题改写为“截至 \(t_1\)”或“最新”条件；
5. 将 \(v_1\) 设为标准答案，\(v_0\) 设为过时答案。

不得直接依赖当前互联网事实作为标签，以免事实变化造成实验不可复现。

## 8. 标签定义

为避免把“答案正确”和“有证据支持”混为一谈，每条记录保留两个标签：

### 8.1 答案正确性标签

回答是否与标准答案一致。短答案使用规范化 Exact Match 和 Token F1；复杂回答采用规则匹配并辅以人工抽检。

### 8.2 证据支撑标签

回答中的关键事实是否得到当前检索证据支持：

- supported：关键事实均有有效证据支持；
- unsupported：关键事实没有证据支持；
- contradicted：回答与有效证据矛盾；
- outdated：回答使用了不符合问题时间条件的旧事实。

主任务将 unsupported、contradicted 和 outdated 合并为幻觉正类，supported 为负类。分组实验保留原始类别。

对于“答案碰巧正确但检索结果没有支持证据”的情况：

- 正确性标签为正确；
- 证据支撑标签为 unsupported；
- 在主任务中计为 grounding hallucination；
- 在报告中单独分析，不能直接称为事实错误。

### 8.3 人工抽检

分层抽取 100 条：

- 正常条件 25 条；
- 检索失败 25 条；
- 证据冲突 25 条；
- 答案过时 25 条。

人工检查构造是否自然、标准答案是否正确、证据是否充分、自动标签是否合理。至少两名成员独立判断，对分歧样本讨论后记录最终结论，并报告一致率。

## 9. RAG 管道实现

### 9.1 语料预处理

1. 保留原始数据集、split、question_id 和 source_id；
2. 清理多余空白，但不改写原文事实；
3. 按自然段建立文档单元；
4. 为每个文档保存稳定 ID；
5. 建立 BM25 索引。

### 9.2 检索

- 默认 Top-K 为 5；
- 同时保存 Top-1、Top-3、Top-5 结果；
- 记录每篇文档的检索分数和排名；
- 使用验证集选择 Top-K，不在测试集上调整。

### 9.3 生成

提示词要求模型只能依据给定证据回答；证据不足时应明确拒答。生成配置固定并写入 YAML：

- temperature：0；
- do_sample：false；
- 要求输出一个简短事实答案或明确拒答，避免无关的长篇扩写；
- 最大新 token 数固定；
- 记录模型名称、权重版本、量化方式和提示词版本。

每条记录保存问题、证据、回答、标准答案、生成配置和运行时间。

## 10. 基线实现

### 10.1 基线 B0：生成模型自评置信度

在生成答案后，将相同的问题、证据和回答再次交给生成模型，要求仅输出 JSON：

```json
{
  "support_probability": 0.73
}
```

提示词必须强调评估“回答是否完全受到给定证据支持”，不能让模型按自身记忆判断世界知识是否正确。

定义：

\[
r_{self}=1-support\_probability
\]

为减少解析错误，温度设为 0，并对非法输出进行一次固定格式重试。失败记录不能静默删除。

### 10.2 基线 B1：MiniCheck-Flan-T5-Large

MiniCheck 接收文档和待验证句子，输出该句受到证据支持的分数。多句回答按句切分，分别评分。

主要聚合方式固定为：

\[
r_{mini}=1-\min_i support_i
\]

即只要有一句关键陈述缺乏支持，整个回答的幻觉风险就会上升。平均支持分数作为补充结果，不用测试集选择聚合方式。

先按照官方代码在 LLM-AggreFact 或论文明确使用的公开子集上复现一项主要指标，目标是与公开结果相差不超过 2 个百分点；如果由于模型版本、硬件或数据版本无法达到，应保留完整配置并解释差异。之后再在本项目测试集上运行。复现记录包含模型版本、数据版本、官方结果、本地结果和差异。

### 10.3 可选基线

如果核心实验已经完成，可增加以下一个轻量基线：

- 回答与证据的向量相似度；
- Vectara HHEM；
- LettuceDetect。

可选基线不能挤占数据质量检查、消融和报告撰写时间。

## 11. 拟研究的方法

### 11.1 方法定位

MiniCheck 主要判断一句回答是否受到某段文档支持，但不会显式区分：

- 检索结果是否足以回答问题；
- 多篇证据是否互相矛盾；
- 某条证据是否已经过时。

本项目拟实现一个**类型感知的证据一致性判别器**，分别估计检索失败、证据冲突和答案过时的风险，再得到总体幻觉风险。

该方法属于待验证的小型方法创新。在最终报告中只能根据文献检索和实验结果描述贡献，不预先使用“首次”或“当前最优”等无法证明的表述。

### 11.2 输入特征

#### 检索充分性特征

- Top-1、Top-3、Top-5 检索分数；
- Top-1 与后续文档的分数差；
- 问题与证据的语义相似度；
- 问题关键词在 Top-K 证据中的覆盖率；
- 多跳支持句的覆盖比例。

#### 回答—证据一致性特征

- 回答句对证据句的最大蕴含概率；
- 最大矛盾概率；
- 检索证据与生成回答的词汇重叠度，包括 Token F1 和 ROUGE-L；
- 回答与证据的语义相似度；
- 回答关键实体在证据中的覆盖率；
- 数字、日期、人物和地点是否匹配；
- 回答中未对齐到任何证据的内容比例。

#### 证据冲突特征

- Top-K 证据两两之间的最大矛盾概率；
- 对同一实体或关系出现的不同值数量；
- 支持回答与反对回答的证据数量；
- 支持和反对证据的检索分数差。

#### 时间有效性特征

- 问题中是否包含时间约束；
- 回答和证据中的日期是否匹配；
- 回答采用的事实版本是否为问题条件下的有效版本；
- 旧版本和新版本证据之间是否存在明确更新关系。

### 11.3 模型结构

第一版采用三个子评分和一个总评分：

```text
检索充分性特征 ──> 检索失败风险
证据冲突特征 ────> 冲突风险
时间有效性特征 ──> 过时风险
全部特征 ─────────> 总体幻觉风险
```

每个子评分使用逻辑回归或小型 MLP。模型同时预测：

1. 是否发生 grounding hallucination；
2. 条件类型，即正常、检索失败、证据冲突和答案过时四类。

不训练新的文本编码器，只训练特征层判别器。

### 11.4 成对约束

每个挑战样本都对应一个正常版本。训练时除二分类损失外，可对“正常版本受到支持、挑战版本确实产生幻觉”的有效样本对增加排序约束，使挑战版本的幻觉风险高于正常版本：

\[
L=L_{binary}+\lambda\max(0,m-(r_{challenge}-r_{clean}))+\beta L_{type}
\]

其中：

- \(L_{binary}\)：幻觉二分类损失；
- \(r_{challenge}\)、\(r_{clean}\)：同一问题挑战版和正常版的风险；
- \(m\)：期望风险间隔；
- \(L_{type}\)：三类失败的分类损失；
- \(\lambda\)、\(\beta\)：只在验证集上选择。

如果模型在挑战条件下正确拒答或仍然回答正确，则不得对该样本强制施加上述排序约束。该约束只利用标签已经确认的有效样本对，目标是减少模型只记住某一种表面模式的情况。

## 12. 实验设计

### 12.1 主实验

在完全相同的测试集上比较：

1. 生成模型自评置信度；
2. MiniCheck-Flan-T5-Large；
3. 本项目完整方法。

### 12.2 指标

主指标：

- ROC-AUC。

辅助指标：

- PR-AUC；
- Macro-F1；
- Precision 和 Recall；
- Brier Score 或 ECE，用于评价风险分数校准；
- 混淆矩阵。

所有指标同时报告总体结果和三类挑战条件下的分组结果。

### 12.3 阈值

分类阈值只能在验证集上选择。测试集只使用一次，不允许根据测试结果反复调阈值。

### 12.4 随机种子

采用分层种子，明确区分构造、划分和训练三个作用域：

| 种子 | 设置 | 作用 |
|---|---|---|
| `construction_seed` | 固定一个值，例如 20260918 | 只用于选择基础问题、实体替换、冲突值和时间版本，生成唯一的一套 900 条正式数据 |
| `split_seed` | 至少三个值，例如 13、42、2026 | 对同一套缓存数据执行三次分组划分 |
| `train_seed` | 与三次实验一一对应 | 控制训练集打乱和判别器初始化 |

主实验只运行一次挑战构造。生成模型采用确定性推理，对 900 条样本生成一次回答，并将回答、自评置信度、MiniCheck 分数和全部固定特征按 `sample_id` 缓存。后续三个种子只改变分组划分和判别器训练，直接读取缓存，不重复运行生成模型和公开基线。

每个 `split_seed` 都必须满足：

- 按 `source_id` 分组，同一问题的正常版和挑战版进入同一集合；
- 正常、检索失败、证据冲突和答案过时四类条件在各集合中大致均衡；
- 三种方法在该种子的同一测试集上比较；
- 验证集只用于阈值和超参数选择，测试集不参与调整。

固定构造种子意味着主实验没有覆盖挑战构造随机性，必须在局限性中说明。如果算力允许，可更换一次 `construction_seed`，在较小子集上补充构造鲁棒性检验；该补充实验需要重新生成回答和基线结果，不与主实验缓存混用。

这种设置使三次正式实验能够共享耗时结果，同时满足单张不超过 12 GB 显存、全部核心实验在 48 小时内完成的限制。

### 12.5 统计检验

- 报告三个 `split_seed/train_seed` 组合的均值±标准差；
- 每个种子内的不同方法必须使用相同测试样本，保证比较成对；
- 按课程要求对三次成对结果使用配对 t 检验或 Wilcoxon 符号秩检验，但同时说明三个种子的统计功效有限；
- 对每个测试集的 AUC 以及 `AUC_ours-AUC_self`、`AUC_ours-AUC_mini` 使用配对 bootstrap 给出 95% 置信区间；
- 显著性水平设为 0.05。

### 12.6 消融实验

完整方法之外，必须完成以下五组主消融：

1. 去掉检索充分性特征；
2. 去掉回答—证据一致性特征；
3. 去掉证据冲突特征；
4. 去掉时间有效性特征；
5. 去掉成对排序损失。

回答—证据一致性是课题指定的核心特征组，其中包括蕴含概率和检索—生成重叠度。为判断两类信号是否互补，在五组主消融之外再完成两组内部消融：

1. 只去掉蕴含和矛盾概率；
2. 只去掉词汇重叠、语义相似度和实体覆盖特征。

所有特征在正式实验前统一提取并缓存。消融实验只重新训练轻量判别器，不重新运行生成模型、MiniCheck 或文本编码器，因此五组主消融均为必做项。

### 12.7 失败分析

至少整理以下类型的失败案例：

- 模型依靠参数记忆答对，但证据缺失；
- MiniCheck 找到局部支持，却忽略较新的冲突证据；
- 时间表达抽取失败；
- 合成冲突文本不自然，导致检测过于简单；
- 回答包含多个事实，整体标签掩盖了局部幻觉；
- 自评置信度异常高但回答错误。

## 16. 主要风险及处理

### 16.1 自评基线过弱

处理：仍按题目要求报告，同时加入 MiniCheck 强基线，避免只与弱方法比较。

### 16.2 无法超过 MiniCheck

处理：课程硬目标是相对自评基线提升 0.10。对 MiniCheck 报告总体和分类型结果；即使总体未超过，也可分析本方法在哪一类有效、在哪一类失败。

### 16.3 合成数据特征过于明显

处理：保留未见过的构造模板用于测试；检查文本自然度；报告正常版和挑战版的长度、词汇等分布，避免模型只学习表面格式。

### 16.4 标签依赖待评估模型

处理：标签由原始答案、构造操作和版本记录确定。NLI、MiniCheck 和本方法都不能参与生成真实标签。

### 16.5 答案过时构造不可信

处理：使用明确的版本时间和更新关系；不声称合成案例等同于全部真实世界时效问题；在结论中限定适用范围。

### 16.6 算力或时间超出限制

处理：优先减少样本量到满足要求的规模，不增加更大的生成模型；缓存检索、生成和 MiniCheck 结果，避免重复推理。
