# 数据构造规范（课题 C09）

> 负责人：A（B/C 复核）。本文规定挑战子集的**构造算子、参数、种子、标签推导与质量核验**。
> 产物字段定义见 [`接口契约.md`](接口契约.md) §2.1；本册只讲"怎么造"，不讲"怎么存"。

## 1. 目标与规模

| 项 | 约定 |
|---|---|
| 挑战集规模 | **≥300 例**（满足课题书要求） |
| 三类配比 | 检索失败、证据冲突、答案过时各 **100 例**（三类均衡） |
| 每类的内部结构 | 50 个**基样本**，每个基样本生成 2 条：**污染版** + **对照版**（同类问题、证据完好） |
| 常规集 | `normal_set.jsonl`：SQuAD v2 dev 抽样 300 条 + HotpotQA validation 抽样 300 条 |
| 划分 | `dev-fit`（判别器训练/调参）与 `dev-test`（报告用）按 **基样本** 7:3 划分，污染版与对照版**必须同侧**（禁止跨侧泄漏） |
| 数据来源 | 在线加载：`load_dataset("rajpurkar/squad_v2")`、`load_dataset("hotpotqa/hotpot_qa", "distractor")`，见 [`项目启动与实施指南.md`](项目启动与实施指南.md) §1.4 |

**只用 dev / validation 划分，不用 train**：生成模型的预训练语料可能已包含 SQuAD/HotpotQA 训练数据，用 train 会引入记忆效应，把"参数记忆"误判成"证据利用"。该风险需在报告"可信度边界"中如实声明。

## 2. 三类退化算子

### 2.1 算子 A：检索失败（`retrieval_failure`）

| 项 | 内容 |
|---|---|
| 定义 | 候选段落中**移除全部 gold 证据句**，替换为同主题干扰段落，使检索器无法命中支撑证据 |
| 实现 | ① 由 `supporting_facts` 定位 gold 句；② 从同源语料中取同主题（同 `title` 之外、词面相似度高的）段落构造干扰项；③ HotpotQA 的 distractor 配置天然提供 8 篇干扰文，优先直接使用 |
| 参数 | `n_replace`（替换句数，默认 2）、`distractor_pool`（干扰来源：`native` \| `sampled`）、`min_lexical_overlap`（干扰段与问题的词面重叠下限，默认 0.2，避免干扰过弱） |
| 观测目标 | 模型是否在**无支撑证据**时仍给出具体答案（"无据陈述"） |

### 2.2 算子 B：证据冲突（`evidence_conflict`）

| 项 | 内容 |
|---|---|
| 定义 | 在证据中**注入与 gold 矛盾但表面可信**的句子（模板生成），或混合两篇互斥证据 |
| 实现 | ① 识别答案中的**可替换槽位**（人名 / 日期 / 数量 / 地点）；② 用同类实体替换生成矛盾句（如 "X 出生于 1990 年" → "X 出生于 1985 年"）；③ 注入位置随机但需落在上下文中部（依据 *Lost in the Middle* 的位置敏感性结论，中部更易被忽略/误用） |
| 参数 | `slot_type`（`person` \| `date` \| `number` \| `place`）、`n_inject`（默认 1）、`inject_position`（默认 `middle`） |
| 观测目标 | 模型采信被注入的错误值，还是坚持 gold 证据 |

### 2.3 算子 C：答案过时（`outdated`）

| 项 | 内容 |
|---|---|
| 定义 | 把**时间敏感**事实改写成过期版本，构成"证据本身正确、但相对当前真值已过时"的场景 |
| 实现 | ① 从含明确日期/任期/记录的事实中筛出时间敏感样本；② 用早于当前真值的版本替换（历史值来自同段落的旧表述或构造的合规版本）；③ 保留一个"当前版本"作为 gold |
| 参数 | `time_gap_years`（过期幅度，默认 ≥2 年）、`gold_version`（当前值） |
| 观测目标 | 一致性特征对"证据自洽但与世界当前状态不符"是否**天然不敏感**（预设的负结果方向，见 [`实验与评估规范.md`](实验与评估规范.md) §7） |
| 风险 | SQuAD/HotpotQA 中时间敏感事实稀少，若筛不出足量样本，按 [`项目启动与实施指南.md`](项目启动与实施指南.md) §6 降级为探索性分析并如实报告 |

## 3. 标签推导（**必须规则化，禁止用待评估的模型信号**）

标签 `is_hallucination` 定义为 **1 − is_supported**，即"该回答是否被所给证据支持"。判定完全由**规则**完成，不使用 NLI 特征——否则标签与特征同源，属于循环论证，结论无效。

| 挑战类型 | `is_supported = 1` 的条件 | `is_supported = 0` 的条件 |
|---|---|---|
| 检索失败 | 模型**拒答**（输出命中拒答模板：`无法回答` / `insufficient information` / 空答案） | 模型给出任何具体答案（因为 gold 证据已被移除，该答案无证据支持） |
| 证据冲突 | 答案匹配注入前的 gold 值（规范化后精确/包含匹配） | 答案匹配注入的错误值 |
| 答案过时 | 答案匹配当前版本 gold 值 | 答案匹配过期版本值 |
| 对照版（三类共用） | 答案匹配 gold 值 | 答案既不匹配 gold 也不匹配任何干扰值 |

配套记录两个附加字段（不参与主任务，用于讨论）：

- `is_factual`：答案相对**世界真值**是否正确（用于区分 "无据但正确"（参数记忆）与 "无据且错误"）；
- `answer_evidence_span`：答案在证据中的匹配片段（若有），便于人工抽检。

> 若某样本按上表无法判定（如答案既不匹配 gold 也不匹配任何注入值），标为 `undetermined` 并**排除出主评估**，同时记录排除数量——不得把无法判定的样本硬塞进正类或负类。

## 4. 参数与种子管理

| 项 | 约定 |
|---|---|
| 构造种子 | `data_seed = 1000 + idx`（idx 为基样本序号），**独立于模型种子** `[13, 42, 2024]` |
| 为什么独立 | 换模型种子时挑战集必须**逐字节不变**，否则消融比较的是"不同数据集"而不是"不同模型配置" |
| 参数记录 | 每条样本的 `construct_params` 字段完整记录算子与参数（见 [`接口契约.md`](接口契约.md) §2.1） |
| 构造日志 | `data/processed/construct_log.json`：算子、参数、种子、各类数量、产物 SHA-256、脚本版本 |
| revision 固定 | 加载数据集时固定 `revision`（提交哈希）并写入 `construct_log.json` 与产物元信息 |

## 5. 施工顺序与质量门禁

```
① 每类各 20 例原型（共 60 例）
      ↓  G3-a 门禁：人工逐条核对标签与构造是否自洽，正确率必须 100%
② 放量到三类各 100 例（共 300 例）
      ↓  G3-b 门禁：随机抽检 100 例（三类按比例），报告一致率与 Cohen's κ
③ 冻结：打版本标签 v1，写入 construct_log.json，此后只增不改
      ↓
④ normal_set.jsonl（600 条）同步生成并冻结
```

- **第 ② 步必须由非作者复核**（B 或 C 抽检 A 的样本），作者自检不作为通过依据；
- 一致率 <90% 时回到 ①：先修判定规则，不允许"放宽阈值凑通过"；
- 冻结后的任何修改都必须新起版本（v2）并说明原因，旧版本结果保留。

## 6. 常见坑与对策

| 坑 | 后果 | 对策 |
|---|---|---|
| 用 NLI 模型判标签 | 标签与特征同源，AUC 虚高，结论不成立 | 严格 §3 的规则化判定 |
| 污染版与对照版跨 dev-fit/dev-test 划分 | 数据泄漏，测试指标虚高 | 按基样本划分，成对同侧 |
| 干扰段落过弱（词面完全不重叠） | "检索失败"退化为"明显无关"，难度失真 | 设 `min_lexical_overlap` 下限，并在原型阶段人工确认干扰"看起来相关" |
| 模型恰因参数记忆答对 | 把"记忆"记成"证据使用失败" | 记录 `is_factual`，在报告中区分讨论；只用 dev/validation 划分 |
| 无法判定的样本硬塞类别 | 标签噪声污染指标 | `undetermined` 单列并排除，数量如实报告 |
| 构造脚本随参数变化而未记版本 | 无法复现挑战集 | 参数全量入 `construct_params` + `construct_log.json` + 产物哈希 |
