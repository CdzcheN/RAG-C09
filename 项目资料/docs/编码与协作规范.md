## 2. CLI 运行入口

### 2.1 统一约定

每个可运行模块实现 `python -m <模块路径>.cli`，共享参数：

| 参数 | 含义 | 默认 |
|---|---|---|
| `--config` | 配置文件路径（YAML） | `configs/default.yaml` |
| `--seed` | 随机种子（覆盖配置） | 配置中的第一个种子 |
| `--out` | 输出目录 | 按 [`接口契约.md`](接口契约.md) §3 的默认路径 |
| `--limit` | 只处理前 N 条（冒烟用） | 全部 |
| `--dry-run` | 只校验配置与输入，不执行重计算 | 关闭 |
| `--exp-id` | 运行 ID；缺省时按命名规则自动生成 | 自动 |

其余模块专属参数写入 YAML 配置，不堆在命令行。

### 2.2 主要入口

```bash
# 0) 环境自检（每次开工前）
python scripts/check_env.py --report results/env_report.json

# 1) 构造挑战集与常规集（A）
python -m src.datasets.challenge_builder --config configs/challenge.yaml --seed 1000
python -m src.datasets.split             --config configs/challenge.yaml

# 2) RAG 管道与基线（B）
python -m src.generation.pipeline --config configs/default.yaml --seed 13 --limit 20   # 冒烟
python -m src.generation.baseline_confidence --config configs/default.yaml --seed 13

# 3) 特征提取（B）
python -m src.features.build_features --config configs/default.yaml --seed 13

# 4) 判别器训练与评估（C）
python -m src.detection.train     --config configs/detect.yaml --seed 13
python -m src.evaluation.grouped  --exp-id w4-consistency-logreg-13
python -m src.evaluation.significance --exp-ids w4-consistency-logreg-{13,42,2024}
python -m src.evaluation.plots    --exp-id w4-consistency-logreg-13
```

### 2.3 退出码

`0` 成功；`1` 输入/配置错误；`2` 运行期中失败（异常已写入日志）；`3` 产物校验不通过（[`接口契约.md`](接口契约.md) §6）。CI/脚本据退出码判断，**不得**用"打印警告但返回 0"掩盖失败。

### 2.4 演示入口（`要求.md` 交付物 4）

`python -m src.demo.app --question "..."`：输入问题 → 显示检索证据 → 显示幻觉判定与分数。演示脚本与实验代码共用同一 `pipeline.py`，避免"演示与实验两套逻辑"。

## 3. 配置与可复现

- 全部超参进 `configs/*.yaml`，代码内**不得**出现魔法数；
- `config_hash` = 对配置内容（排序键、去注释）取 SHA-256 前 12 位，写入每份产物元信息；
- 配置变更需在周会说明，并在 [`实验记录.md`](实验记录.md) 的决策记录中登记；
- 数据集与模型都固定 `revision`（HuggingFace 提交哈希）并写入元信息。

## 4. 日志与失败处理

```python
from src.common.logging_utils import get_logger
log = get_logger(__name__)      # 同时输出到 stdout 与 results/logs/<exp_id>.log
```

- 每次运行必须落一份日志，含：命令行、`config_hash`、种子、数据集/模型 revision、耗时、异常栈；
- 日志级别：`INFO` 默认记录进度与关键参数，`DEBUG` 记录逐样本细节（默认关闭，避免大文件）；
- **不允许半成品产物**：先写 `<name>.tmp`，全部成功后再 `rename` 为正式名；失败时删除临时文件；
- 长任务每 N 条打印一次进度（`tqdm` + `logging`），便于判断是否卡死。

## 5. 随机性与跨平台

- 唯一入口 `src/common/seeding.py::set_seed(seed)`：内部设置 `random`、`numpy`、`torch.manual_seed`、`torch.cuda.manual_seed_all`、`transformers.set_seed`；**禁止**在实验代码里散落 `np.random.seed`；
- 严格可复现的算子（如判别器训练）设置 `torch.use_deterministic_algorithms(True)` 并记录是否因性能关闭；
- 4 GB 显存约束（见 [`项目启动与实施指南.md`](项目启动与实施指南.md) §1.3）：解码统一 `do_sample=False`；`batch=1` 为默认；
- 跨平台（Ubuntu/Windows）：
  - 路径一律 `pathlib.Path`，**不要**手写 `\` 或 `/` 拼接；
  - 文件读写显式 `encoding="utf-8"`（Windows 默认 GBK 会乱码/报错）；
  - 不使用 `os.fork`、shell 特有语法（`<<EOF`、`sed -i` 等）；需要多进程时用 `multiprocessing` 的 spawn 兼容写法；
  - 终端输出避免 emoji 与复杂制表符（Windows 控制台可能无法显示），必要时设 `PYTHONUTF8=1`。

## 6. 代码风格

- Python 3.10；每个模块首行 `from __future__ import annotations`；全部函数带类型标注；
- 模块级 docstring 必写（用法、输入输出、依赖）；公开函数写 docstring；
- 用 `argparse`（不用 click，减少依赖）；用 `dataclasses`（见 `src/common/schema.py`）；
- 单文件 ≤400 行，超了就拆；函数 ≤60 行为宜；
- 提交前自检：`python -m compileall src scripts` 通过、`python scripts/smoke_test.py` 通过。

## 8. 依赖管理

- 只改 `requirements.txt`（新增包注明用途与是否必需）；
- 不执行 `conda install torch/torchvision`（会与 PyPI 轮子冲突，见 [`项目启动与实施指南.md`](项目启动与实施指南.md) §1.1 约定 ③）；
- 装完新依赖必须重跑 `python scripts/check_env.py` 并更新 [`实验记录.md`](实验记录.md) 的环境变更记录。

## 9. 测试与冒烟

| 层级 | 内容 | 触发时机 |
|---|---|---|
| 冒烟 | `python scripts/smoke_test.py`：20 条样本端到端跑通 + 产物校验（[`接口契约.md`](接口契约.md) §6） | 每次改动核心模块后、每次合并前 |
| 单元 | `tests/` 下针对 `overlap.py`（F1 计算）、`seeding.py`（可复现性）、`metrics.py`（指标口径）的 pytest | 新增/修改这些模块时 |
| 回归 | 同一 `exp_id` 重跑，指标落在既有 `mean ± std` 内 | 接口或特征定义变更后 |

**冒烟测试是合并闸门**：谁的改动让 `main` 上的冒烟失败，谁负责先修（见下）。

## 10. 协作纪律

- **仓库**：协作仓库位于团队自己的位置，本工作区只承载文档、数据与实验产物（不使用 Git）；
- **分支**：`main` 仅接收合并；A/B/C 各一条长期分支；实验在 `exp/*` 上跑；
- **合并窗口**：每周固定一次，只合并"可运行 + 有验证（冒烟通过）"的改动；
- **互审**：报告章节交叉互审（A↔B、B↔C、C↔A）；代码改动涉及接口或指标口径时，须由对应文档负责人复核；
- **坏 `main` 先修后议**：不争论责任，先把冒烟修绿；
- **周会前 1 小时**：各自在最新 `main` 上重跑冒烟，绿了才允许合并。
