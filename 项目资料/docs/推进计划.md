# 推进计划：A / B / C 的任务与执行节奏

> 本文件把 [`项目启动与实施指南.md`](项目启动与实施指南.md) §3（流程图与门禁）、§4（分工与 WBS）与
> **当前代码骨架的实际状态**对齐，回答两个问题：**每个人接下来做什么**、**项目怎么推进**。
> 记号：`W_k ≡ 教学周 6+k`；门禁 G0–G6 的定义见指南 §3.1。

## 1. 推进总原则

1. **依赖链**：A（数据）→ B（管道与特征）→ C（判别与评估）。这条链本身是串行的，
   但用**假数据桩**可以把它切成并行（见下条）；
2. **并行破局点**：接口（`src/common/schema.py`）已实现并冻结，因此
   - B 不等 A 的真实挑战集：先用**假检索桩**（随机/固定 top-k 段落）跑 `pipeline.py`；
   - C 不等 B 的真实特征表：先用**假特征桩**（`FeatureRow` 随机数值）打通训练与评估；
   三人因此可以在同一周内各自推进，而不是排队等待；
3. **门禁先行**：每阶段有可验证的通过条件，未过不进下一阶段（避免在错误基线上继续投入）；
4. **每人都有"可失败的实验"**：A/B/C 各负责 1 组消融，天然满足"≥3 组消融"的要求。

## 7. 协作机制（每周重复）

1. **周会（40 min，固定时点）**：每人 3 分钟、以数字说话 → 当场补 [`实验记录.md`](实验记录.md) 的周会表；宣布本周门禁是否通过；
2. **合并窗口（每周 1 次）**：只合并"可运行 + 冒烟通过"的改动；`python scripts/smoke_test.py --with-tests` 是合并闸门；
3. **接口变更**：任何字段增删改走 [`接口契约.md`](接口契约.md) §5 流程（提案 → 全组确认 → 同步下游 → 20 条回归）；
4. **阻塞上报**：任何一项阻塞超过半天立即在群里说明（如"A6 的时间敏感样本不足"），不要自己憋着；
5. **实验登记**：每次运行登记 `exp_id` 与指标，确保报告中的每个数字都能追溯到 `results/metrics/`。

## 9. 风险与预案

| 风险 | 触发信号 | 预案 |
|---|---|---|
| 环境未就绪（当前唯一硬阻塞） | `check_env.py` 非 0 | 按指南 §1.2 补装；镜像走 hf-mirror；不要用旧环境 |
| 挑战集标签无法自动判定 | A5 原型正确率 <100% | 改判定规则；仍不行则半自动 + 人工确认，并如实报告比例 |
| "答案过时"样本不足 | A2/A6 阶段筛不出足量 | 降低该类占比或降级为探索性分析，在报告中声明（允许负结果） |
| AUC 增益 <0.10 | C4 单种子验证集增益 <0.05 | 走迭代回路：误差分析 → 补特征（引用覆盖率/span 对齐/多证据投票）→ 换判别器 → 校准 |
| 4 GB 显存不够（生成 + NLI 同驻） | `CUDA out of memory` | 生成与 NLI 分时复用显存；降 `max_new_tokens`；必要时 1.5B 转 CPU |
| 生成吞吐不足 | 全量推理预估 >12 h | 常规集抽样规模下调（300 → 200），先保证挑战集全量；把抽样规模写进报告 |
| 三人进度脱节 | 周会出现"等人" | 立即启用假数据桩解耦；必要时把 A6 的放量拆成两批交付 |
